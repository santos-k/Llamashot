Snipping Toolbar Design

How should the new capture toolbar look when PrintScreen is pressed?

Screen is dimmed & frozen — draw to select region

A: Integrated into OverlayWindow

Add the snipping toolbar as a new element inside the existing OverlayWindow. When PrintScreen is pressed, the overlay opens with the toolbar at the top center instead of immediately starting region selection. Less new code, reuses existing screen capture and dimming.

Pros

  • Reuses existing overlay infrastructure
  • Single window manages everything
  • Less code to maintain

Cons

  • OverlayWindow.xaml.cs is already complex
  • More state to manage in one class
SnippingToolbar is a separate window, coordinates with OverlayWindow

B: Separate SnippingToolbar Window

Create a new SnippingToolbar window that appears over a dimmed overlay. The toolbar handles mode selection, then launches the appropriate overlay (OverlayWindow for screenshots, RecordingOverlay for video). Clean separation of concerns.

Pros

  • Clean separation — toolbar logic isolated
  • OverlayWindow stays focused on annotation
  • Easier to test and modify independently

Cons

  • Two windows to coordinate (toolbar + dim overlay)
  • More code overall
  • Need to pass state between windows

Toolbar Buttons (both approaches)

📷 ScreenshotDefault mode. Blue underline when active.
🎥 VideoSwitch to video recording mode.
📐 Capture Mode ▾Dropdown: Region (default), Window, Fullscreen
🔍 OCRText extraction mode — extract, copy, dismiss
⏱ Delay ▾Dropdown: None, 1s, 3s, 5s, 10s
✕ CloseDismiss the toolbar and overlay
Recommendation: Approach A (integrated) — OverlayWindow already handles screen capture, dimming, region selection, and all annotation. Adding the snipping toolbar as another state in the same window avoids dual-window coordination headaches and keeps the codebase simpler.
