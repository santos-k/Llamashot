01

What's broken today

Each tool is its own near-empty page: a title, a filename, a couple of inputs, and a giant button floating in a sea of dark.

Issue 01

~90% empty space

A single column of controls centred in a maximised window. No use of width, no density, nothing to anchor the eye.

Three-column workspace fills the canvas: preview · settings · info.
Issue 02

No file preview

Users can't see the document or page order, so they don't trust merge/split/extract results before committing.

Persistent live preview + page thumbnails on every tool.
Issue 03

Disconnected action

The lone primary button sits far from the files it acts on, with no sense of "what" or "how many".

Sticky action bar: Clear · selection count · Process — always in reach.

①

Tool rail

Add Files, Workspace (All/Recent/Starred/Trash), and the full tool list. Shared file context — switch tools without re-uploading.

②

Preview canvas

Live page render, thumbnail strip, pager, zoom & rotate. Identical component everywhere — users always see what they selected.

③

Settings (the only variable)

The per-tool widget. Same primitives — segmented cards, ranges, checkboxes, sliders — composed differently per tool.

④

Info panel

File details, contextual Helpful Tips, and Recent Files. Pure shared chrome.

⑤

Action bar

Clear All · live selection count · the Process button. Sticky, consistent label per tool.

04

One component, every tool

A single ToolPage shell. Each tool is just data + a settings widget — no new screens, no duplicated chrome.

// Shared shell — built once, reused by all 14 tools. class ToolPage { title: "Split PDF", subtitle: "Split PDF pages into multiple files", previewPanel: true, // ② live render + thumbnails + pager + zoom infoPanel: true, // ④ file info · tips · recent settings: SplitSettings(), // ③ the ONLY per-tool part actionLabel: "Split PDF", // ⑤ sticky bar button multiFile: true, // selected-files dock + "apply to" scope onProcess: files => FileToolsService.splitPdf(files, opts), suggestNext: ["compress", "watermark", "page_numbers"], } // Every tool collapses to one line. ToolPage(MergeSettings) ToolPage(CompressSettings) ToolPage(SplitSettings) ToolPage(RotateSettings) ToolPage(WatermarkSettings) ToolPage(PdfToImageSettings) …

In WPF terms: one UserControl (ToolPageView) with three ContentPresenter slots. The current 21 hand-built panels collapse into 14 small settings DataTemplates + a shared preview/info/action chrome — deleting thousands of duplicated XAML lines.
